## Schema

`corpus.parquet`: one row per patent document.

| Column | Meaning |
|---|---|
| `patent_id` | Unique id. Publication number for applications (`US20160220097A1`), `US` plus patent number for grants |
| `source` | `HUPD_APP` or `PV_GRANT`. Shown in the UI |
| `title`, `abstract` | Cleaned text |
| `filing_date`, `publication_date`, `grant_date` | ISO dates. `publication_date` is the prior-art date used by search filters. `filing_date` is empty for `PV_GRANT` |
| `assignee` | Empty for `HUPD_APP` (not provided by HUPD) |
| `cpc_codes` | CPC codes in source order, main code first. HUPD codes are group-concatenated without a separator (for example `G06F1730268`), only the first four characters (the subclass) are reliable |
| `cpc_subclasses` | Unique subclasses (first four characters), used for filtering and CPC voting |
| `main_subclass` | Subclass of the first code |
| `n_claims`, `n_independent`, `n_summary_words`, `url` | Counts and a Google Patents link |

`chunks.parquet`: one row per retrievable unit.

| Column | Meaning |
|---|---|
| `chunk_id` | Stable id `<patent_id>:<chunk_type>:<seq>`. Embedding resumes by this key |
| `chunk_type` | `claim`, `abstract`, `summary`, `description` |
| `claim_number`, `is_independent`, `parent_claim` | Set for claims only. Numbers are as published, canceled claims are dropped so gaps can occur |
| `seq` | Claim number for claims, passage index otherwise |
| `text` | Chunk text. Summary and description passages are whole sentences of 15 to 150 words, targeting 80 to 150 |
| `char_start`, `char_end` | Offsets into the cleaned source field the chunk came from (the claim itself, the abstract, the summary or the description). `text == field[char_start:char_end]` |
| `n_words` | Word count |

## Cleaning rules

- Unicode NFC, control characters removed, whitespace collapsed.
- HUPD: `<SOH> heading <EOH>` markers and XML residue removed, the replacement character before
  a digit restored to the section sign, upper-case titles converted to title case.
- Claims: a claims blob is split on sequential numbering only, so numbers inside a claim body do
  not create splits. Range markers such as `1-20. (canceled)` advance the sequence and canceled
  claims are dropped. A claim is dependent when its first 300 characters reference an earlier
  claim, and the first such claim number is stored as `parent_claim`.
- Summary and description are capped per patent (`--max-summary-chunks`, default 20, and
  `--max-description-chunks`, default 40) to keep the embedding job tractable on CPU.
- Filter: a patent is kept when any of its CPC subclasses is in G06N, G06F, G06Q, G16H, H04L,
  H04W, H01M, B60L, A61B, C12N. Patents without claims or without abstract and summary text are
  dropped and counted in `build_stats.json`.

## Reproduce

```
uv sync
uv run python scripts/download_hupd.py --sample
uv run python scripts/build_corpus.py --hupd dataset/raw/hupd/data/sample-jan-2016.tar.gz --write-demo
uv run python scripts/validate_corpus.py
uv run python scripts/update_dataset_readme.py
```

For the full demo corpus add `--years 2013 2014` to the HUPD download and pass the archives to
`--hupd`. For granted patents resolve the current PatentsView file locations (see below), then
run `download_patentsview.py --years ...` and `build_corpus.py --patentsview-years ...`.
